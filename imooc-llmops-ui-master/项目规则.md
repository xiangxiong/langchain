# 项目规则文档

## 一、代码规范

### 1. ESLint规范
- 继承规则：
  - `plugin:vue/vue3-essential`
  - `eslint:recommended`
  - `@vue/eslint-config-typescript`
  - `@vue/eslint-config-prettier/skip-formatting`
- 解析器选项：ECMAScript最新版本

### 2. Prettier规范
- 半角分号：不使用
- 缩进：2个空格
- 引号：单引号
- 行宽：100字符
- 尾随逗号：所有情况都使用

### 3. 代码风格
- 变量声明：优先使用`const`，其次使用`let`，禁止使用`var`
- 箭头函数：当只有一个参数时，省略括号；当函数体只有一行时，省略花括号
- 模板字符串：优先使用模板字符串代替字符串拼接
- 解构赋值：优先使用解构赋值获取对象或数组的属性
- 展开运算符：优先使用展开运算符代替`Object.assign()`
- 可选链和空值合并：优先使用`?.`和`??`

## 二、TypeScript规范

### 1. 配置
- 继承：`@vue/tsconfig/tsconfig.dom.json`
- 包含文件：`env.d.ts`、`src/**/*`、`src/**/*.vue`
- 排除文件：`src/**/__tests__/*`
- 路径别名：`@/*` 指向 `./src/*`

### 2. 类型使用
- 接口命名：使用`I`前缀（如`IUser`）
- 类型别名：使用`T`前缀（如`TUserList`）
- 泛型：合理使用泛型提高代码复用性
- 类型断言：优先使用`as`语法，避免使用尖括号语法
- 非空断言：谨慎使用`!`，确保变量确实非空
- 可选属性：合理使用`?`标记可选属性

### 3. 最佳实践
- 避免使用`any`类型，尽可能使用具体类型
- 使用`unknown`类型代替`any`类型处理未知数据
- 为函数参数和返回值添加类型注解
- 为组件的props和emits添加类型定义
- 使用`interface`定义对象类型，使用`type`定义联合类型或交叉类型

## 三、目录结构规范

### 1. 目录结构
```
src/
├── assets/           # 静态资源
│   ├── images/       # 图片资源
│   ├── styles/       # 样式文件
│   └── logo.svg      # 项目Logo
├── components/       # 公共组件
│   ├── icons/        # 图标组件
│   └── ...           # 其他公共组件
├── config/           # 配置文件
├── hooks/            # 自定义Hooks
├── models/           # 数据模型定义
├── router/           # 路由配置
├── services/         # API服务
├── stores/           # Pinia状态管理
├── utils/            # 工具函数
├── views/            # 页面组件
│   ├── auth/         # 认证相关页面
│   ├── errors/       # 错误页面
│   ├── layouts/      # 布局组件
│   ├── openapi/      # OpenAPI相关页面
│   ├── pages/        # 首页等基础页面
│   ├── space/        # 空间管理页面
│   ├── store/        # 应用商店页面
│   └── web-apps/     # Web应用页面
├── App.vue           # 根组件
└── main.ts           # 入口文件
```

### 2. 目录职责
- **assets/**：存放静态资源，包括图片、样式、Logo等
- **components/**：存放公共组件，按功能或类型分类
- **config/**：存放项目配置文件
- **hooks/**：存放自定义Hooks，按功能命名
- **models/**：存放TypeScript类型定义和接口
- **router/**：存放路由配置
- **services/**：存放API服务，按功能模块划分
- **stores/**：存放Pinia状态管理，按功能模块划分
- **utils/**：存放工具函数，按功能分类
- **views/**：存放页面组件，按功能模块划分

## 四、组件设计规范

### 1. 组件命名
- 组件名称使用PascalCase（如`AppLayoutView`）
- 文件名与组件名保持一致
- 公共组件放在`components/`目录下
- 页面组件放在`views/`目录下

### 2. 组件结构
```vue
<template>
  <!-- 模板内容 -->
</template>

<script setup lang="ts">
// 组件逻辑
</script>

<style scoped>
/* 组件样式 */
</style>
```

### 3. 组件设计原则
- 单一职责：每个组件只负责一个功能
- 可复用性：设计通用组件时考虑复用场景
- 可维护性：组件结构清晰，易于理解和修改
- 性能优化：避免不必要的渲染和计算

### 4. Props和Emits
- Props：使用`defineProps`定义，添加类型注解和默认值
- Emits：使用`defineEmits`定义，添加类型注解
- 事件命名：使用kebab-case（如`update:model-value`）

### 5. 样式规范
- 使用Tailwind CSS进行样式开发
- 组件样式使用`scoped`属性
- 全局样式放在`assets/styles/main.css`
- 样式类名使用kebab-case

## 五、Hooks设计规范

### 1. Hooks命名
- 使用`use-`前缀（如`use-auth`）
- 文件名与Hooks名保持一致
- 按功能模块划分Hooks

### 2. Hooks结构
```typescript
export function useExample() {
  // 状态定义
  const state = ref(initialValue)
  
  // 计算属性
  const computedValue = computed(() => {
    return state.value * 2
  })
  
  // 方法定义
  const method = () => {
    // 方法逻辑
  }
  
  // 返回值
  return {
    state,
    computedValue,
    method
  }
}
```

### 3. Hooks设计原则
- 单一职责：每个Hooks只负责一个功能
- 可复用性：设计通用Hooks时考虑复用场景
- 状态封装：将相关状态和方法封装在Hooks中
- 副作用管理：合理使用`watch`、`onMounted`等生命周期钩子

## 六、命名规范

### 1. 文件命名
- 组件文件：PascalCase（如`AppLayoutView.vue`）
- Hooks文件：kebab-case，使用`use-`前缀（如`use-auth.ts`）
- 工具函数文件：kebab-case（如`auth.ts`）
- 类型定义文件：kebab-case（如`account.ts`）

### 2. 变量命名
- 普通变量：camelCase（如`userName`）
- 常量：UPPER_CASE，使用下划线分隔（如`MAX_LENGTH`）
- 状态变量：camelCase，使用`ref`或`reactive`定义
- 计算属性：camelCase，使用`computed`定义

### 3. 函数命名
- 普通函数：camelCase（如`getUserInfo`）
- 异步函数：camelCase，使用`async`关键字（如`fetchUserInfo`）
- 事件处理函数：camelCase，使用`on`前缀（如`onClick`）

### 4. 类命名
- 类名：PascalCase（如`UserService`）
- 接口命名：PascalCase，使用`I`前缀（如`IUser`）
- 类型别名：PascalCase，使用`T`前缀（如`TUserList`）

## 七、注释规范

### 1. 注释类型
- 单行注释：使用`//`，用于简短说明
- 多行注释：使用`/* */`，用于详细说明
- JSDoc注释：使用`/** */`，用于函数、类、接口等的文档注释

### 2. 注释规范
- 组件注释：为组件添加功能说明和使用方法
- 函数注释：为函数添加参数、返回值和功能说明
- 复杂逻辑注释：为复杂的业务逻辑添加注释
- 常量注释：为常量添加说明
- 类型注释：为接口和类型别名添加说明

### 3. JSDoc示例
```typescript
/**
 * 获取用户信息
 * @param userId 用户ID
 * @returns 用户信息对象
 */
export async function getUserInfo(userId: string): Promise<IUser> {
  // 函数逻辑
}
```

## 八、Git规范

### 1. 分支规范
- `main`：主分支，用于发布生产版本
- `develop`：开发分支，用于集成开发功能
- `feature/xxx`：特性分支，用于开发新功能
- `bugfix/xxx`：修复分支，用于修复bug
- `release/xxx`：发布分支，用于准备发布版本

### 2. Commit规范
- Commit信息格式：`type(scope): subject`
  - `type`：提交类型，如`feat`、`fix`、`docs`、`style`、`refactor`、`test`、`chore`
  - `scope`：提交范围，如`auth`、`app`、`workflow`
  - `subject`：提交主题，简洁明了

### 3. Commit类型
- `feat`：新功能
- `fix`：修复bug
- `docs`：文档修改
- `style`：代码格式修改（不影响代码逻辑）
- `refactor`：代码重构（不新增功能，不修复bug）
- `test`：测试代码修改
- `chore`：构建工具或依赖修改

### 4. 提交示例
- `feat(auth): 添加OAuth授权功能`
- `fix(app): 修复应用发布失败问题`
- `docs(readme): 更新项目说明文档`
- `refactor(workflow): 重构工作流节点配置逻辑`

### 2. 设计阶段
- 技术方案设计
- 接口设计

### 3. 开发阶段
- 创建分支：从`develop`分支创建特性分支

- 创建发布分支：从`develop`分支创建发布分支
- 版本测试：在发布分支上进行最终测试
- 合并到主分支：将发布分支合并到`main`和`develop`分支

- 构建项目：运行构建命令
- 部署到测试环境：进行测试环境验证

## 十一、性能优化规范

### 1. 代码优化
- 避免不必要的渲染：使用`v-memo`、`v-once`等指令
- 合理使用计算属性：避免在模板中进行复杂计算
- 组件按需加载：使用动态导入
- 图片优化：使用合适的图片格式和大小

### 2. 大型列表优化
- 使用虚拟滚动：`vue-virtual-scroller`
- 合理设置`key`：使用唯一ID作为`key`
- 避免深度监听：减少`watch`的使用

### 3. 网络优化
- API请求合并：避免频繁请求
- 缓存策略：合理使用缓存
- 懒加载：按需加载资源
- CDN加速：使用CDN加载静态资源

## 十二、安全规范

### 1. XSS防护
- 使用`v-html`时确保内容安全
- 对用户输入进行过滤和转义

### 2. CSRF防护
- 使用CSRF Token
- 验证请求来源

### 3. 敏感数据处理
- 不在前端存储敏感数据
- 对敏感数据进行加密传输

### 4. 权限控制
- 前端权限验证
- 后端权限验证
- 路由守卫控制访问权限
